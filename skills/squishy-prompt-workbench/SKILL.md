# 捏捏提示词工作台

## 概述

专属于**捏捏/解压/感官玩具类目**生图流水线。本技能只负责**流程编排**，提示词内容规则一律以工作区内的规则文件为唯一权威，禁止在本技能里复制第二份规则。

## 工作区定位（零硬编码，开工前必先解析）

本技能不绑定任何固定盘符/用户名。第一步是解析工作区根目录 **`<WB>`**：

1. 读 `%USERPROFILE%\.workbuddy\squishy-workbench.json`（**UTF-8 带 BOM，必须用 `utf-8-sig` 读**）→ 取 `workbench_dir` 字段作为 `<WB>`
2. 文件不存在、字段为空、或该目录无效 → **立即停止**，提示用户先运行仓库根目录的 `install.ps1`。禁止猜测路径。
3. 技能目录本身可能是**目录联接（Junction）**，属正常状态，不要"修复"、不要复制、不要在其内部写文件。

约定：下文所有工作区文件路径都写作 `<WB>\...`。

## 路径表（`<WB>` = 上面的 workbench_dir）

| 用途 | 路径 |
|---|---|
| 身份权威全文 | `<WB>\identity.md` |
| 规则沉淀库（F/P 规则） | `<WB>\feedback.md` |
| 通过版案例库 | `<WB>\library.md` |
| 生图脚本（唯一入口） | `<WB>\scripts\generate_hermes.py` |
| 中转站配置（含 key） | `<WB>\config\api.json` |
| 参考图 / 提示词 / 出图 | `<WB>\ref\` · `<WB>\prompts\` · `<WB>\outputs\` |
| 每日工作日志 | `<WB>\.workbuddy\memory\` |
| 工作区巡检 | 用 `prompt-workbench-audit` 技能 |

**为什么 `scripts/` 是复制而不是链接**：`generate_hermes.py` 用 `Path(__file__)` 反推工作区根（`ROOT = 脚本上一级目录`），并把读写路径强制收敛到 `ROOT` 之内。若用链接，`resolve()` 会跟到仓库目录，导致 `ref/`、`outputs/` 被判越界而拒绝执行。故脚本必须真实落在 `<WB>\scripts\`。规则文件（`*.md`）无此问题，由 `update.ps1` 复制同步。

## 权威优先级（冲突时按此判）

1. `<WB>\identity.md` — 人格 + 铁律 + 色板 + 四图规则 + 终审清单
2. `<WB>\feedback.md` — 用户纠正沉淀（F=图文规则 / P=流程违规），**最新条款优先**
3. `<WB>\library.md` — 已验证通过版案例（风格与文案可复用）
4. 本技能 — 仅流程编排

## 已知规格（勿假设其他；尺寸未说明必须先问）

- 万圣节捏捏：直径 5cm ｜ 白色幽灵：15cm
- 黄油条：长 11cm / 13cm，长径比 2.6:1；规格 4OZ / SALTED / BUTTER / NET WT. 113 G → 默认**平躺**，禁自创立起
- 布丁杯宽 5cm ｜ 组合品比例必须写进提示词（如黄油条 ≈ 布丁 2.5 倍长）

## 生图环境（硬约束）

- 中转站与模型写在 `<WB>\config\api.json`：模型**仅 `gpt-image-2`**，`model_locked=true` 时**禁止切任何 -1k/-2k/-4k 变体**
- 参考图商品细节敏感时用 `--endpoint edits`（像素级保留）；多张参考图要先 PIL 拼成单底图再 edits，**禁止让模型从多图"提取商品"**
- 429 `image_queue_full`：间隔拉到 ~60s 重试，勿连环轰炸、勿换模型绕
- 502：等 6-8s 重试
- 实测 36-60s/张；请求 1024x1024 实际回 1254×1254 属正常

## When to Use

- 用户要求"写捏捏生图提示词""给白色幽灵/黄油条出图""捏捏乐套图"
- 用户要求"复盘捏捏提示词库""进化身份"
- 其他类目（美妆/Temu 全类目）→ 用对应类目技能，禁止串类目

## Process

1. **确认范围**：商品、图类型与张数、节日/风格、尺寸。**范围以用户最后一条指令为准，不自行加量**；「刚生成的图」类指代=字面最近一张产出，有歧义先问一句。
2. **读权威**：`<WB>\identity.md` + `<WB>\feedback.md`（F/P 全量）+ `<WB>\library.md` 检索同类案例。
3. **写中文稿**（`<WB>\prompts\<前缀>_draft_cn.md`）：按八段模板——①商品基准声明（含计数锁/印刷锁）②类目色板分支+背景禁忌 ③风格基调句（五维：配色+光线+氛围+画质+字体）④主图 ⑤宣传图1（手捏徽章）⑥宣传图2（卖点图标）⑦实际使用图 ⑧终审自检表。
   - **中文稿必须全中文**：英文句意用中文写出，画面文案词用「英文原文+中文释义」标注。
   - 提示词**不描述商品外观/填充物**，最小识别集=指代词+计数+比例+印刷锁。
4. **停下等 OK**：回复最后一字必须是向用户要 OK 的问题，**该轮不带任何生图工具调用**。用户明确 OK 前 `generate_hermes.py` 一次都不能跑（永久闸门）。
5. **转英文**：4 张 × 4 段（`[Composition & Layout]` / `[Background & Lighting]` / `[On-Image Text]` / `[Style & Quality]`），全英文、`//` 结尾。每张单独成文件（禁多图合稿）。
6. **逐张生图**：先出主图 → 用户过目 → 再批量其余。命令逐条单独执行、逐条核对文件，**禁多张链式一锅跑**。
   ```powershell
   cd <WB>
   python scripts\generate_hermes.py --prompt-file prompts\<前缀>_main.txt --ref ref\<前缀>_ref.png --endpoint edits --name <前缀>_main --size 1024x1024
   ```
   没有 `python` 时改用 WorkBuddy 自带解释器 `%USERPROFILE%\.workbuddy\binaries\python\envs\default\Scripts\python.exe`。
7. **P3 自查**（交付前必跑）：逐图核对①`[On-Image Text]` 每行是否都有 horizontal 约束②禁用词（提示词与图内文字双向扫）③文字层数达标 ④not food 声明 ⑤静态件 UNDEFORMED ⑥徽章捏压四件套 ⑦`//` 结尾唯一。声明层全过一遍 + 图像层先目检一轮，再交用户终检。
8. **交付**：用 `present_files` 卡片给 `<WB>\outputs\` 内文件（工作区外路径卡片不渲染），配**一行简短说明**，不要表格/长段罗列。
9. **入库**：通过版中英对照写 `<WB>\library.md`；纠正写 `<WB>\feedback.md`；当日追加 `<WB>\.workbuddy\memory\YYYY-MM-DD.md`。**改完这两份规则文件后提示用户跑一次 `update.ps1` 并 push**，否则同事拿不到新规则。

## 命名规范（永久）

- 交付图文件名：`*月*日第*个任务的<主图/宣传图1/宣传图2/实际使用图>.png`（如 `9月10日第1个任务的主图.png`），序号按当日任务递增
- 提示词文件可沿用英文 slug

## 硬性密度指标（永久）

| 图 | 最少文字层数 |
|---|---|
| 主图 | ≥2（主标题 + 数量徽章） |
| 宣传图1 | ≥3（大标题 + 徽章弧字 + 促销条/角标） |
| 宣传图2 | ≥4（大标题 + 标语 + 图标词 + 促销条/角标） |
| 使用图 | ≥2（感叹标语 + 底部标语条） |

各图文案不重复、全英文、禁用词零。违反即重做，不再询问。

## 禁用词清单（含变体/拆分/组合，最终以 `<WB>\identity.md` 第七节 + `feedback.md` 为准）

Mystery / blind box / Squishy / Squishy Dumpling / Dumpling / baby / babies / infant / toddler / 1-4 years / early education / Squishmallows / Pop Mart / Jellycat / Disney / Sanrio 等。
**自查必须扫生成图内文字**（SQUISH 类变体曾两次漏扫）。

## 参考图文字规则

参考图里的文字只复刻样式（位置/字号/字体/颜色/对齐），内容一律新写；原厂印刷（如盒顶 `SQUISHY FUN BOX`）按保真豁免处理但**不新增禁用词**。

## Verification

- [ ] `<WB>` 已解析成功（config json 存在且目录有效）
- [ ] 中文稿八段齐全、全中文、用户已 OK（含张数范围）
- [ ] 英文版 4×4 结构、全英文、零禁用词、基调句四图逐字统一、`//` 结尾
- [ ] 出图后 P3 自查逐项 ✓，图像层已目检
- [ ] 文件名符合中文命名规范
- [ ] `library.md` + `feedback.md` + 当日 memory 已落盘，并已提示用户同步

## Red Flags

- `<WB>` 解析失败还硬着头皮猜路径干活
- 未经 OK 直接转英文或生图（最高频违规）
- 中文稿里夹英文原句
- 提示词描述商品外观/颜色/填充物 → 会被改商品
- 静态陈列图出现变形；密封个体出现珠粒外溢
- 宣传语层数不够、各图重复
- 任何文字竖排/旋转
- 命令行传带括号/空格的中文文件名前未先 `cp` 成纯英文名
- 像素级 PIL 修补超过 2 轮仍不收敛还继续磨（立即改为重生成）
- 命令没报错就当作出图成功（必须核对文件存在 + 时间戳 + 分辨率）
- 直接编辑仓库目录内的文件（应用 `update.ps1` 同步，仓库只写不读）

## 安全约定

- key 只存 `<WB>\config\api.json`，**不进命令行、不写进 identity/library/feedback**；查看配置必须脱敏
- 中文稿发出后的那一轮不执行任何生图命令

## 配套技能

- `prompt-workbench-audit` — 工作区只读巡检（盘点资产 / 查未完成订单 / 查记忆断档）
